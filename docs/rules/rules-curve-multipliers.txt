B1 METHOD. Curves: class C n = 5..20: both senses for n = 5..15, sense -1 for n = 16, 17, 19 and sense +1 for n = 18, 20 (the senses with a zero in the stored files; 27 curves); class I n = 5..20: both senses for n = 5..14, sense -1 for n = 15, 16 and sense +1 for n = 17..20 (26 curves). Arguments: n, theta = the stored member |turns| (data/branch-points/<n>-upper.json and data/class-i/curves/n<n>.json, field member.turns), the default repeat tolerance 1e-9 and the default pieces (8 for all, as stored), the same trace files as the stored runs (data/r-family-trace.json for class C, data/r-family-trace-iso.json for class I). One job per curve for class C (one sense per job), one job per n for class I (the released tool follows both senses; the sense without a zero is followed too, as in the stored run, and is not analysed).
RETRACE CHECK (G), against the stored curve: same number of points; |ds|, |dT*|, |dL*| <= 1e-7 (absolute; the stored files have 10 significant digits), |dturns| <= 1e-9, at every point. A curve that fails (G) is reported and still analysed, marked.
REFERENCE CHECKS, in terms of the quantity y = mu + 1/mu of each eigenvalue (complex numbers allowed), the four y values sorted by (real part, imaginary part), compared with the same four y values of the stored tier A multiplier file (data/stability-mp/class-c/class-c-<n>-A.json; for n = 8 the case 8d (double length orbit data/refined/T47.065.json) for (a) and the case 8s for (b); data/class-i/stability/n<n>-A.json), mu taken from the fields re and im: (a) the reduction applied to the stored 30 digit start of the end orbit (class C: data/refined/T17.847.json for n = 5, T19.769.json for n = 6, T47.065.json for n = 8 (double length), data/satellite-candidates.json (label of the upper branch) for n = 7 and 9..20; class I: data/class-i/refined/n<n>.json), rounded to double, agrees with tier A: max |dy| <= 1e-6 * max(1, |y|); (b) the last point of each analysed retraced curve (the double precision zero) agrees with tier A: max |dy| <= 1e-3 * max(1, |y|). A curve that fails (b) is reported and NOT classified.
CLASSIFICATION. The four eigenvalues are put in two reciprocal pairs: the roots y1, y2 of y^2 - a y + (b - 2) = 0 with a = the sum of the eigenvalues and b = the sum of the products of two (the characteristic polynomial is x^4 - a x^3 + b x^2 - a x + 1); a pair has the eigenvalues x of x^2 - y x + 1 = 0. TYPE of a pair: ELLIPTIC if both moduli are within 1e-6 of 1; REAL POSITIVE or REAL NEGATIVE if both eigenvalues are real (|im| <= 1e-6 |x|) and the moduli are off 1 by more than 1e-6, by the sign of x; COMPLEX QUADRUPLET otherwise (both pairs). (The 1e-6 is above the noise of the reduction seen in the pilot and in the stored class I curves, about 1e-10, and 3e-8 near the branch point.) RELIABLE: a pair is classified at a point only if all its eigenvalues are at least 1e-4 away from +1 and from -1; otherwise the point is "near +-1, not classified" for that pair. The resonant pair is therefore classified from the first point at which it is 1e-4 from +1, and that point (s, L*) is stated per curve; no classification before it.
TRACKING. Per point the two roots y; assignment to "resonant" and "transverse" by continuity: at the first point the resonant pair is the root nearer to 2 (y = 2 is the double +1 of the branch point); at every later point the permutation that minimises |y1' - y1| + |y2' - y2| is taken. A step is AMBIGUOUS if the other permutation costs less than 3 times the chosen one; ambiguous steps are counted and listed (first and last index), and the first-point assignment is ambiguous if the other root is within 1e-2 of 2.
CHANGES OF TYPE. A change of type of a pair counts only if the new type holds for at least 3 consecutive classified points; single-point flips are reported as noise. A change is reported with its bracket: the last point of the old type and the first point of the new type, each with (index, s, L*, theta in turns); points "near +-1" in between are inside the bracket. Brackets only; no refinement of a crossing. For the transverse pair of n = 13..20 the angle alpha_t of the last elliptic point is also reported.
PRIORITY AND ORDER. The jobs of n = 12, 13 and 20, class C and class I, run first (class C n = 12: senses 1 and -1; n = 13: 1 and -1; n = 20: 1; class I n = 12, 13, 20: one job each); then the rest in the order n = 5, 6, 7, 8, 9, 10, 11, 14, 15, 16, 17, 18, 19 (class C jobs before the class I job of the same n). At most 10 jobs run at the same time (the machine has 12 cores), DETACHED (the queue script is started detached and is never stopped by me), my own processes only. A single job is stopped after 120 minutes and reported as stopped. TIME LIMIT of the whole run (B1 + B3): 4 hours of wall clock from the first job of the main run; the queue starts no new job after 3 hours 15 minutes; jobs still running at 4 hours are stopped (own processes) and reported as not finished.

DECLARATION 1 (written after the smoke tests and before the main run; the machine clock read 2026-10-18 14:08:30 right after this text was written). The smoke tests were: the new class C copy on n = 5 sense 1 (124 points, equal to the stored curve in the printed numbers) and analyse-curves.mjs on the STORED class I curve of n = 12. They showed three things, and the rules are changed as follows; thresholds, predictions and everything else stay as written. (1) The first point of a curve (s = 0, the n fold repeat itself) has no multipliers (the reduction fails there, in the stored class I files too: mult.error); it is not classified. (2) The last element of the curve array is the first point PAST the zero (its rotation is 1e-5 to 1e-4 turns), not the zero; check (b) is therefore made AT THE ZERO: the reduction is applied to the start stored in satellite[].zero (u1, u2, lam, t) and compared with tier A as written for (b); the curve itself is classified as stored, its last point included. (3) The noise of the resonant pair is in the invariant y, not in the eigenvalues: y - 2 scatters by about 1e-7 around the branch point, and the two eigenvalues then scatter by sqrt(|y - 2|), about 1e-4 (on the stored class I curve of n = 12, y_R - 2 stays within +-1e-7 up to s = 3 and then reaches -1e-5 and later +3e-3 at the end). The criterion "all eigenvalues of the pair at least 1e-4 from +1 and from -1" is replaced by: a pair is classified at a point only if |y - 2| >= 1e-6 and |y + 2| >= 1e-6 (about ten times the noise of y); the TYPE rules (moduli within 1e-6 of 1, real, complex), the tracking rule and the rule of 3 consecutive points are unchanged. A consequence that I note before the main run: on the stored class I curve of n = 12 the resonant pair is not "real positive along the whole curve" (it is within the noise of y = 2 for most of it, then elliptic with a tiny angle, then real positive in the last part), so prediction P5 may fail; it stays as written (85 percent) and will be reported as it comes out.
