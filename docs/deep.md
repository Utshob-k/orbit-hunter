# The ias route (PeriCont, version 0.3.0)

The close-approach route of the perpendicular start is called PeriCont (version 0.3.0); in the code and in the settings it is the ias route. It goes through close approaches of two bodies to witnessed pair distances of 7.320e-10, 1.907e-9, 8.573e-9 and 1.611e-8 on four families (the stored parabolic estimates of the witnesses, to four digits; the osculating pericentre at the closest sample of the 50 digit flow, `data/deep/extra/pericentres.json`, is 7.319e-10 for t35 - and the same four digits for the other three). Version 0.2.33 and the default of 0.3.0 use the Dormand-Prince code of `src/physics.js`; in the earlier runs of `data/deep/extra/old-variants.json` the closest approach of the tool (a tool value, not witnessed) at the point where it lost the family was 3.8e-4 to 8.1e-4 on t19 -, t35 + and t35 - with the default corrector tolerance 1e-11, and 1.2e-4 to 2.6e-4 on t19 -, t35 +, t35 - and a14 + with the tolerance 1e-10 (the run of a14 + used tighter integrator tolerances). In the corrector of the ias route the end state of every piece of the multiple shooting comes from REBOUND IAS15, and the pieces with a close pair are recomputed with the regularised integrator `src/ias/reg.js`; T* and L* of every accepted step come from the start values alone, and the closest approach and the closure of a recorded point from the Dormand-Prince code (section "Which integrator gives which number"). The results that come out are checked afterwards by a flow in multiple precision (the witnesses, `tools/witness.py`), which does not use any of this code. The limits are in [methods-and-limits.md](methods-and-limits.md) (section "The ias route"). Paths are from the top folder of the repository.

## Which integrator gives which number

- From IAS15 and `reg.js`: the end states of the pieces in the corrector (`reg.js` for the encounter pieces and for the pieces replaced by the cross-check), and the rotation angle theta made from them. IAS15 starts every piece with the first step `settings.ias.firstStep`: 'timescale' (the default: 0.01 times the smallest d / |v_rel| of the three pairs at the start of the piece, at most the piece length) or 'legacy' (REBOUND's default 0.001, which every stored run used; see the first-step bullet in [methods-and-limits.md](methods-and-limits.md)). Everything here that reproduces stored data sets 'legacy' explicitly.
- From the start values alone, without any integration: the energy E, the angular momentum L, T* = 2t |E|^1.5 and L* = |L| |E|^(1/2) of every accepted step, recorded or not (`perpEL` in `src/perp.js`; it uses the same sums as `perpInfo`, so its values equal the `ts` and `ls` of `perpInfo` bit for bit). L has a sign (negative on t35 -); the traces store L* = |L| |E|^(1/2).
- From the Dormand-Prince code of `src/physics.js`: the closest approach `minDist` (the smallest pair distance at the ends of its steps), the closure, and for every fifth point the syzygy word and `maxMod`, all computed by `perpInfo` and `relativeStability`, which integrate the whole orbit (`src/perp.js` has no ias branch); the stop rule `--max-dist`; and the 12 x 12 matrices of the pieces that are neither flagged nor replaced by the cross-check (`src/stability.js`).
- An accepted step is unrecorded when the Dormand-Prince integration of its whole orbit in `perpInfo` exceeds its step limit: it then has no closest approach and no closure from the tool. Its start values and its T* and L* (from the start values) are kept in the list `unrec`, and it is witnessed. The step limit is reached near deep encounters, which is why which steps are recorded can differ between machines. The `unrecorded` lists of the stored traces got `Tstar` and `Lstar` afterwards, computed from their stored start values (no rerun).
- From the multiple precision flow of the witnesses: the closure and the smallest pair distance of a witnessed point (the depths).

## Parts

- `src/ias/ias-bridge.py` is one long-lived Python process per trace. It runs REBOUND IAS15 for one piece at a time and gets its requests as lines of JSON from `src/ias/bridge.js` (through a worker thread, `bridge-worker.mjs`, so the shooting code can stay synchronous).
- `src/ias/guards.py` decides from the sampled pair distances of a piece whether it is an encounter piece and whether one of the guards trips (below). `src/ias/reg.js` is the regularised integrator (algorithmic regularisation in chain coordinates) used for the encounter pieces; `reg-settings.json` has its constants. `src/ias/recorder.js` writes one line per attempt of the corrector.
- `tools/family-follow-ias.mjs` follows a family in one direction and writes the trace. `tools/reproduce-trace.mjs` runs a stored trace again from its command-line start and compares the accepted steps with the stored ones (it prints PASS if they are the same and, without `--stop-after`, the run has as many accepted steps and stops for the same reason; a relative OUT is taken relative to the folder the command is run in). `tools/pack-pericont.mjs` builds the package (below).
- `tools/trace-witnesses.py`, `witness-jobs.py`, `run-queue.py`, `witness.py`, `witness-check.py` make the witnesses of a trace and read them (below). `tools/reclose.py` closes a stored orbit again at the same lam in multiple precision. `tools/point-diagnostic.py` looks at one point that does not close. `tools/guard-check.py` runs the guards on stored orbits.
- `tools/residual-floor.mjs` (the resolution of the corrector residual at accepted steps), `tools/reclose-continue.py` (50 digit continuation in lam from a closed orbit), `tools/pair-angmom.py` (signed angular momentum of the close pair), `tools/piece-ends.mjs` and `tools/piece-mp.py` (end states of the pieces of one step by IAS15, `reg.js` and the Dormand-Prince code against the 50 digit flow) and `tools/dp45-attempts.mjs` (the default route with the record of every attempt of the corrector) are described with the files they made in the table below; so are `tools/piece-trace.py` (TRACE on the same pieces) and the option `--ids` (with `--points`) of `tools/pair-angmom.py`, which takes the points of other traces.
- `src/ias/reg.js` has its own page, [reg.md](reg.md) (arguments, returned fields, failure reasons, what is tested).
- `tools/gate-a-rows.py` and `tools/gate-a.mjs` test `reg.js` against the exact Kepler flow of a pair (`tools/gate-a-unequal.py` makes the row for two unequal masses); `tools/kepler-ref.py`, `kepler-check.py` and `witness-acceptance.py` do the same for the multiple precision flow of the witnesses.

### The guards

A piece is an encounter piece if its smallest sampled pair distance is below 1e-3. A guard trips when

- G1a: the second smallest pair distance is below 0.02 at a sample where the smallest is below 1e-3,
- G1b: at the pericentre of an encounter piece the second distance is below 390 times the smallest (`--guard-ratio`),
- G2: the second smallest of the three per-pair minima of a piece is below 0.02, or two encounter pieces belong to different pairs,
- G3: a node of the multiple shooting has a pair distance below 1e-4.

A trip fails that attempt of the corrector; it does not stop the trace by itself. After five failed attempts in a row with a guard tripping the driver stops with "triple-approach guard", and a trip right after a Newton residual of 1e-10 or less stops it at once. The ratio of G1b is 390 in this release; the stored traces of t35 - and t12 + were run with 400 (column `guard_ratio` of `data/deep/traces-table.csv`). Two more checks do not stop a trace by themselves: an unflagged piece in which `reg.js` finds a closest approach below 1e-3 is counted as a missed flag (the trace stops if it is below 5e-4), and unflagged pieces with a pair distance below `settings.ias.crossCheckBelow` (0.05 by default) are also run through `reg.js` and replaced by its end state where the two differ. The counts are in the `guards` field of the trace file.

The thresholds of the guards are chosen, they are not observed failures. The ratio 390 of G1b is 1.5 times the smallest tested ratio R/d1 at the periapsis distance q = 1e-4 (257.2); none of the 44 rows of `data/deep/extra/gate-a-extension.json` fails at any tested ratio (R/d1 from 50 at q = 1e-3 to 3333; the largest error is 3.6e-3 of its limit), so no tested ratio shows `reg.js` failing. G1a and G2 (0.02) and G3 (1e-4) have no test of their own. A stop by "triple-approach guard" (7 of the 15 traces that were run) therefore says that the chosen threshold was reached, not that `reg.js` was seen to fail there.

The missed-flag check runs `reg.js` (without the matrix) on every unflagged piece of every evaluation (`missedFlagCheck` in `src/ias/bridge.js`). In the full outputs of the 14 traces that have one (not in the compact files; `guards.missChecks` and `guards.tMiss`) it was called 462126 times for t35 - (501013 pieces went through the bridge), 284107 times for t44 - (349827 pieces), 107906 times for t62 - (109406 pieces) and 80524 times for t72 - (84564 pieces), and it took 6.3, 3.4, 5.2 and 4.9 percent of the run time of these four; over all 14 traces 2.3 to 7.4 percent.

### A trace

```
node tools/family-follow-ias.mjs OUT.json DIR u1 u2 lam t [--minutes=120] [--pieces=24] [--label=name] [--max-dist=0.03] [--stop-below=0] [--stop-after=N] [--ias-mode=2] [--ias-first-step=timescale|legacy] [--newton-tol=1e-11] [--no-nodes] [--timeout-min=30] [--python=PY] [--guard-ratio=390] [--tol-scale=K] [--arc-weight=W] [--natural=DL] [--matrix=exact|fd-forward|fd-central] [--handover [--handover-below=1e-7] [--handover-steps=20] [--handover-dlam=1e-5]]
```

DIR is 1 or -1 (the direction in lam), `t` is half the period. `OUT.json` must be new. `--ias-first-step` sets `settings.ias.firstStep` (the value is in the field `settings.ias.firstStep` of the output; the stored traces have no such field and were run with 'legacy', so a command that is meant to reproduce one of them needs `--ias-first-step=legacy`); `--newton-tol` sets `settings.newton`, the stopping tolerance of the corrector residual. The 279 components of every accepted step (u1, u2, t and the 23 node states) are written to `OUT.json.nodes.jsonl`, one line `{step, z}` per accepted step, unless `--no-nodes` is given; that file is, like the others, never overwritten. The start that a stored trace file holds is the start after the first closing that the driver makes; to reproduce a stored trace use `node tools/reproduce-trace.mjs LABEL OUT.json [--stop-after=N]`, which builds the command from the command-line start of `data/deep/extra/start-shift.json`, the direction and the guard ratio of `data/deep/traces-table.json` and `--ias-first-step=legacy`, prints it, runs it and compares the accepted steps with `data/deep/traces/LABEL.json` (given the stored start, the driver closes it a second time and the run can differ from the first accepted step on; see `data/deep/README.md`). The settings that the stored traces used, against the defaults, are in the table at the end of this section. The file has one record for every accepted step that could be recorded (start values, T*, L*, theta, turns, closest approach, closure; T* and L* from the start values, the closest approach and the closure from the Dormand-Prince code), a list `unrec` of the accepted steps for which the closest approach and the closure could not be computed (the Dormand-Prince integration of the orbit exceeded its step limit; their T* and L* are in the list, from the start values), the guard counts and the reason why the trace stopped. The cost of an accepted step, run_seconds / (points + unrecorded_steps) of `data/deep/traces-table.json`, was 0.74 to 6.14 seconds on the 15 traces that were run; a trace is sequential (each step needs the one before).

### The options for the stall and the hand-over

Three options of the driver are off by default and were tried on the stall of t35 - and t44 - (the creep, where the corrector no longer gets below its tolerance): `--tol-scale=K` (the corrector stops when sup|F| < max(newton-tol, K 2^-52 max|J| max(1, max|Y|)); the effective tolerance is written to the diag file as `tolEff`), `--arc-weight=W` (the node components have weight W in the norm of the pseudo-arclength, u1, u2, t and lam weight 1) and `--natural=DL` (natural continuation in lam with the step doubled after at most 3 iterations; it does not look for zeros of theta); `--pieces=48` needs no code. Each was run for 30 minutes on both traces from the last stored accepted step, `--tol-scale=16` and `--arc-weight=1e-3` also together. They do not help: no run reached ten times the progress of the run with newton-tol 1e-10, two of the options stopped early (step length below 1e-9 and 1e-14), and with the scaled tolerance three of five re-closed points of t44 - differ from their 50 digit re-closing by more than 1e-9. The rows are in `data/deep/extra/stall-remedies.json`.

`--handover` stops the double precision steps where the 50 digit continuation is faster and hands over to it. The rule has no wall time: after at least 100 accepted steps P100 = |lam_k - lam_(k-100)| / 100 over the last 100 accepted steps, and if P100 < `--handover-below` (1e-7 by default) the driver closes the last accepted point again with `tools/reclose.py` (the point itself is the reference, the closing must converge) and runs `tools/reclose-continue.py` from it for `--handover-steps` steps (20) of `--handover-dlam` in lam (1e-5, in the direction of the last step of lam, which is the sign of DIR unless lam has turned at a fold; the direction is recorded in the block), with the w1 witness of the last orbit; the `handover` block of OUT.json has the rule, the re-closing, every 50 digit step (lam, u1, u2, t as strings), the witness and the exit status of every process (`exits`), and the stop reason is "handed over to the 50 digit continuation" only if the re-closing converged and at least one 50 digit step converged. Otherwise it is "hand-over failed: <reason>" (the re-closing wrote no output or did not converge, the continuation wrote nothing, or its first step did not converge, with the status of the step) and the driver exits with 1 (`tools/handover-run.mjs`, `test/handover-fail.test.js`). Whether the re-closed point is the same orbit as the double precision point (`same_orbit_as_the_point_itself`, within 1e-9) is recorded and not required: in the creep the double precision point can be off the orbit by more than 1e-9 (on family m at lam 0.99987 by 2.4e-9, 2.9e-8 and 8.6e-8 in u1, u2 and t), and the 50 digit point is the better one. `lamMinWithHandover` and `lamMaxWithHandover` of OUT.json are the range of lam with the converged 50 digit steps. The limit 1e-7 comes from the costs: the 50 digit continuation makes 1e-5 in lam in 148.6 s (t35 -) and 293.9 s (t44 -), and this route takes about 1.8 to 2.9 s per accepted step before the creep. Run from the command-line start of the stored traces (`node tools/reproduce-trace.mjs t35m OUT.json --handover --minutes=90`, and t44m), the rule fired after 262 and 286 accepted steps (lam 0.66385188 and 0.22907662; the stored traces reached 99 % of their lam range at the accepted steps 198 and 124 and began to creep at 1221 and 624), and those accepted steps are bit for bit those of the stored traces. The 20 steps of the 50 digit continuation all converged, went 1.89e-4 and 1.93e-4 beyond the last lam of the stored traces, and the w1 witness of the last orbit passes. The orbit at the lam of the last step of the 50 digit continuation of `data/deep/extra/reclose-continuation-beyond.json`, closed again from the hand-over steps, is the same orbit as that step (1e-9). The runs took 4656 s and 8081 s; the double precision parts took 1049 s and 1821 s, which is 4.0 and 6.4 s per accepted step on this machine at that time (1.8 to 2.9 s in the stored runs before the creep) (`data/deep/extra/handover.json`; `test/handover-rule.test.js` tests the rule on made-up lam sequences).

### The creep rule

A trace creeps if the step in lam falls by orders of magnitude. The rule works on the accepted steps (the recorded points and the unrecorded steps in the order of the loop step) with d_k = |lam_(k+1) - lam_k|: m0 is the median of the first 500 d_k; the trace creeps if the median of its last 500 d_k is at most m0 / 100 and there is a start. The creep starts at the smallest accepted step k such that at least one window of 100 consecutive d_j starts at or after k (j >= k) and the median of every such window is at most m0 / 100. If the last window of 100 is already above m0 / 100 there is no start and the trace does not creep (a trace whose steps grow again at the end is not creeping; with fewer than 1000 accepted steps the rule is not applied). `tools/creep-attempts.py` has the rule and tells, from the per-attempt records, what the corrector does in the creep and before it (`data/deep/extra/creep-attempts.json`); t35 -, t44 - and t81 - creep, from the loop steps 1491, 668 and 333, and t14 + and t72 + do not (the t14 + that an earlier reading of the rule listed had no window at the end).

### The bound on t in the line search

The line search of the corrector (`correct0` and `correctNat0` in `src/shooting.js`) skips a trial point whose t (half the period) is below 0.3 or above 3 times the t of the predicted point. The bound guards against a jump to another orbit within one Newton solve, not against the family changing its period. Before this change it was relative to the t of the start of the run. That did no harm on the 14 stored ias traces (t / t0 is between 0.584 and 1.308 along them; t62 - and t72 - are reproduced bit for bit over their whole length with the new bound, 375 and 325 accepted steps, and t35 - over its first 262 accepted steps), but along Hénon's family m t falls from 1.30 to 0.39 at lam 0.668 (0.3 times the start), and the trace stopped there with "step length below 1e-9": one unit in the last place of the nodes moved F by 7e-16, IAS15 was within 1e-16 of the 50 digit flow on all pieces, the 50 digit continuation went on smoothly, and the Newton step was there but every trial point was rejected by the bound. With the bound relative to the predicted point the trace goes through Hénon's orbits 42 to 46 (lam 0.739 to 0.944) on to lam 0.99988, 1.2e-4 short of the collision at lam = 1 where his table ends (A to infinity); the re-closed orbits 42 and 46 agree with his converted values to 1.1e-8 and 1.2e-8, the level of his printed digits (`data/deep/extra/henon-family-m.json`). `test/t-bound.test.js` follows the family from his orbit 5 for 174 loop steps (not for a time, so the result does not depend on the speed of the machine) and needs lam above 0.67. The drivers record a point with `maxMod` null and a field `stabilityError` when `relativeStability` throws (124 of the 493 checked points of this run, all beyond lam 0.9957, where the eigenvalue iteration of the monodromy matrix does not converge), count them in `stabilityErrors` and go on; the run ends by the creep of the corrector at a closest approach of 1.2e-4 (all 24 pieces are encounter pieces, the largest row sum of the piece matrices is 3.5e5), as t35 - and t44 - do. The same bound was in `src/iso-shooting.js` (class I) and in `src/shooting.js` when the stored Dormand-Prince results of the satellites of R were made, and some of those results ended at it, described as "collapse of the step" or "lost the family": the one sense of each class I curve for n = 15 to 20 that stopped (`data/class-i/curves/`, t / t0 = 3.000004 to 3.000006 at the last point), the trace through A1 in the direction -1 (`data/a1-family-corotation.json`, lost the family near lam = -0.6495 at 0.2999975 t0), the run F1 of the extended trace of R (`data/r-family-trace-extended.json`, 0.29999 t0) and the class C upper curves for n = 16 to 36, where the stored curves have no t but the rerun shows it: rerun with the bound relative to the predicted point (`data/rerun-0.3.0/`), the stopped sense of every n from 16 to 36 reaches a rotation 0 at the orbit of the other sense (510 to 693 points for n = 16 to 22; 723 to 1275 points for n = 23 to 36, where the limit of 700 steps of `tools/branch-point.mjs` had to be raised with `--max-steps=1500`). The code of this release does not reproduce stored Dormand-Prince results that reached the old bound; the stored files are not changed, the reruns are in `data/rerun-0.3.0/` (class I: `src/iso-shooting.js` has the bound relative to the predicted point as well).

### Finite differences instead of the derivative of reg.js

The driver can build the 12 x 12 matrix of a flagged piece (and of a piece replaced by the cross-check) from finite differences of `reg.js` instead of its derivative: `--matrix=fd-forward` takes forward differences with the increment 1e-7 max(1, |x_c|), as Henon (1974) did with his regularised Bulirsch-Stoer flow, `--matrix=fd-central` central differences with 1e-5 max(1, |x_c|); the default is `exact`. On the 10 flagged pieces with the smallest pair distance of `data/deep/extra/piece-check-mp.json` (7.3e-10 to 1.1e-4) the largest error of an entry against a 60 digit central-difference reference, in units of the largest entry, is 1e-13 to 1.7e-11 for the derivative of `reg.js`, 1.2e-7 to 8.1e-5 for forward and 6.6e-10 to 7.7e-5 for central differences (the median ratio to the exact matrix on the four pieces below 1e-7 is 4.5e4 and 276), and the matrix takes 21 to 32 ms, 32 to 66 ms and 63 to 122 ms per piece. In the corrector, t35 - (31 recorded points from the replay start) takes a median of 7 Newton iterations per accepted step and no failed attempt with the exact matrix (336 s), but 11 iterations and 8 or 9 failed attempts with either finite-difference variant, whose accepted step falls from 0.2 to 1.6e-3 and 7.8e-4, so that they reach only 10 and 5 recorded points in the 120 minutes that the driver allows; t44 - (40 recorded points) takes a median of 5 iterations and 1 failed attempt with the exact matrix, 10 and 5 with forward and 6 and 3 with central differences, and all three reach the end. By the rule that was fixed before the runs the exact derivative gains over both variants (`data/deep/extra/fd-comparison.json`). The reference matrix is made by `tools/fd-reference.py` (24 flows of the 60 digit flow of `tools/refine-mp.py` per piece, from the start states that `tools/piece-ends.mjs` writes; its usage line has the commands).

### The witnesses

A witness integrates the stored start values (u1, u2, lam, t) over the whole orbit in multiple precision, with the Gragg-Bulirsch-Stoer flow of `tools/refine-mp.py` and nothing from `src/ias/`: preset `w1` 40 digits, flow tolerance 1e-26, smallest step 1e-14; preset `w1b` 50 digits, tolerance 1e-30, smallest step 1e-20. It records the smallest pair distance and the closure of the full period, and `tools/witness-check.py` adds the relative change of the energy and of the angular momentum (both must stay below 1e-14). A point counts as witnessed if the w1 minimum of the pair distance is 1e-7 or more, or the w1b minimum is 1e-10 or more, the closure is below 1e-6 and the check passes; below those minima the flow is not accepted (see the limits).

```
python tools/trace-witnesses.py points TRACE.json POINTS.json      # which points: every point whose lam is at least 0.01 s from the last kept one (s is the median |dlam| of the first 20 recorded steps, or --s), and the unrecorded steps
python tools/witness-jobs.py POINTS.json W1DIR QUEUE.json          # job files and the queue
python tools/run-queue.py QUEUE.json 3                             # three at a time
python tools/witness-check.py W1DIR --out W1CHECK.json
python tools/trace-witnesses.py select W1DIR LOW.json              # the points below 1e-7: w1b for these (witness-jobs.py ... --preset w1b)
python tools/trace-witnesses.py summary TRACE.json W1DIR W1BDIR --checks W1CHECK.json --checks-w1b W1BCHECK.json
```

The summary gives the strict chain (the points in the order of the steps, cut at the first point that is not witnessed), the smallest witnessed minimum before the cut (the "strict witnessed depth") and whether the witnessed closest approach turns (a witnessed minimum followed by a rise of a factor 2 or more with witnessed points on both sides; this is all that "turns" means here, it is not a turn of the family). The witnessed points are the kept points and the unrecorded steps, not every accepted step: 69 of the 1711 accepted steps of t35 -, 124 of 1266 of t44 -, 336 of 375 of t62 -, 325 of 325 of t72 -; the witness files store the s that was used, and `reading --trace` prints how many recorded points were not selected. One witness takes 14 to 172 seconds with w1 (median 26 to 43 seconds on the four stored traces) and 26 to 106 seconds with w1b; the witnesses of a whole trace of 300 points are an hour or two with three jobs at once.

`docs/pericont-files.txt` lists the files of PeriCont (version 0.3.0): `src`, the tools of this page, the tests of `npm test` and `npm run test:ias`, `data/deep`, the documents, a `README.md` of its own (`docs/pericont-readme.md` in the repository), `CITATION.cff`, `CHANGELOG.md`, `LICENSE` (MIT: code), `LICENSE-DATA` (CC BY 4.0: data, documents, README) and `package.json`. `node tools/pack-pericont.mjs OUTDIR` builds `pericont-0.3.0.zip` from that list into a folder outside the repository (190 files, 1.9 MB). The sha256 of the zip depends on the line endings of the checkout (a checkout with CRLF gives another zip than one with LF, with the same files), because the repository has no `.gitattributes`; quote the number of files and the size, not the checksum. Unpacked into a new folder with `ORBIT_PYTHON` set (above), `npm test` gives 46 PASS, `npm run test:ias` 135 PASS (4 to 10 minutes) and `node tools/deep-sample.mjs` PASS (6 to 15 minutes), with no FAIL; `test/ias-first-step.test.js`, a diagnostic of REBOUND's default first step, is in the package but not in the script.

## Sample run

```
node tools/deep-sample.mjs
```

follows the family of t35 - from its stored start for 4 recorded points (25 accepted steps, 21 of them not recorded), makes the witnesses of all 25 (w1, and w1b for the points below 1e-7) and prints the summary. It checks numbers against `data/deep/sample/expected-summary.json` and prints PASS or FAIL: the recorded points (4) and the accepted steps (25), the witnessed points (25 of 25), the strict witnessed depth (7.3197e-10 at step 10, relative tolerance 1e-3), lam of the last point (relative 1e-9), the closure of every witness below its acceptance limit 1e-6, that the closest approach turns, and no guard trip. It runs the trace with `--guard-ratio=400`, the ratio of the stored t35 - trace. The summary text is compared with `data/deep/sample/expected-summary.txt` as information only (it depends on the machine: which steps are recorded, lam to 8 decimals, the w1 minima to 6 digits). Without `--dir DIR` the files go to a new folder `orbit-hunter-sample-XXXXXX` in the temporary folder of the operating system (it is not deleted); `--dir` names a new folder instead. It took 331 seconds on the machine of the stored run (trace 109 s, w1 witnesses 146 s, w1b witnesses 76 s); a first run with other jobs on the machine took 621 seconds; expect 6 to 12 minutes. The whole output of the stored run is `data/deep/sample/output.txt`.
